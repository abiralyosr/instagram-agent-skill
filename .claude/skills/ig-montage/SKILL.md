# ig-montage

Turns the user's footage into a Reel that looks like an agency cut it. The
engine is `reelforge.py` in this folder. It does the mechanics; you make the
editorial decisions, and every decision you make goes into `edit.json` where
the user can read it.

```bash
python3 reelforge.py doctor                        # what this machine can do
python3 reelforge.py new abir-atib "lancement oud"  # project folder under <repo>/reels/
python3 reelforge.py probe  PROJECT                # inventory, contact sheets, pauses, loudness
python3 reelforge.py subs   PROJECT                # script.txt + voice -> subs.srt
python3 reelforge.py plan   PROJECT                # first-draft edit.json
python3 reelforge.py check  PROJECT                # lint before any render
python3 reelforge.py render PROJECT --preview      # 540x960 review copy
python3 reelforge.py render PROJECT --final        # 1080x1920 master
python3 reelforge.py render PROJECT --dry-run      # print the ffmpeg commands only
```

Nothing here spends credits. It runs FFmpeg locally. Still, **never render
without the user's go-ahead**: say what the cut will be, then render.

## The rules that make it premium

These come before any tool. A machine edit looks machine-made because it
breaks these. The linter catches some of them, and you are responsible for
the rest.

1. **The cut is the transition.** Hard cuts by default. A crossfade or a fade
   to black is a punctuation mark: one into the payoff, one into the end card.
   The brand profile caps the ratio (`max_transition_ratio`). Never two of the
   same soft transition in a row. No wipes, no spins, no glitch, no zoom
   transitions, no flashes.
2. **Cut on meaning or on movement.** A shot changes when the sentence changes
   (`plan` aligns cuts to subtitle starts) or when something moves: a hand
   enters, a cap comes off, a head turns. Look at the contact sheets and pick
   `in` points where the action starts. Never cut in the middle of a gesture.
3. **Vary the rhythm.** Never three shots of the same length in a row. Shorter
   shots under the hook, longer ones on the product and the payoff.
4. **The first frame moves.** Open on video, not a still. The hook text and the
   first spoken word are on screen inside the first second.
5. **Photos breathe, they don't fly.** One slow eased move per photo (5-7 %
   zoom or drift), never the same move twice in a row, never a Ken Burns on a
   photo shorter than 2 s.
6. **One look per brand.** The grade comes from the brand profile. Per-shot
   `grade` overrides are only for matching a shot that is darker, cooler or
   flatter than its neighbours, never for a "style".
7. **Sound is half the premium.** The voice is clean, warm and in front. The
   music sits under it and ducks when the voice speaks. A little real ambient
   sound from the footage stays in (−24 to −26 dB) so it feels filmed, not
   assembled. Master at −14 LUFS, −1.5 dBTP.
8. **Subtitles are read, not watched.** Two lines max, about 26 characters a
   line, in the Instagram safe zone (above the caption, clear of the right-side
   buttons), a soft shadow and no box unless the background fights it. No
   word-by-word karaoke and no bouncing.
9. **End clean.** The last spoken word lands, the music tails, the logo card
   fades in. No "follow for more" card.

## Workflow

### 1. Intake

Create the project with `new BRAND "title"`. It makes:

```
reels/<brand>/<date>-<slug>/
  inputs/video/  inputs/photo/  inputs/voice/  inputs/music/
  script.txt     one subtitle line per line, in Tunisian darija, as spoken
  edit.json      the cut (all decisions)
  subs.srt       generated by `subs`, then corrected by hand
  out/           contact sheets, work files, renders (not in git)
```

Put the user's files in the right `inputs/` folder. Name rushes in story
order (`01_ouverture.mov`, `02_flacon.mov`...) when the user gives an order.
If there is no script yet, write it first with `/ig-reel` (and the brand
skill for Abir Atib) and have the user record the voice-over from it.

### 2. Probe and look

`probe` writes `out/probe.json` (duration, resolution, fps, HDR, scene
changes, voice pauses, loudness) and one contact sheet per video in
`out/contact/` with timestamps. **Open every contact sheet and every photo
with Read before deciding anything.** Note for each clip: what is in it, the
best 2-3 s, where the action starts, whether it is shaky, dark or
horizontal, and where the subject sits in frame (`focus_x`).

### 3. Subtitles

`script.txt` is the source of truth for the words, because no automatic
transcription handles Tunisian darija reliably. Write one spoken phrase per
line, exactly as said in the voice-over, including French words the speaker
uses. `subs` places the lines on the voice-over's pauses and writes
`subs.srt`. Read it back against the voice and fix the timings by hand when
a line is late or early. `subs` refuses to overwrite a corrected file
without `--force`.

### 4. The cut

`plan` writes a first draft: length from the voice, cuts on phrase starts,
media interleaved, one soft transition, the end card. **It is a draft.**
Rewrite it from what you saw in the contact sheets:

```json
{
  "brand": "abir-atib",
  "title": "lancement oud",
  "voice": "inputs/voice/vo.wav",
  "voice_offset": 0.3,
  "music": {"file": "inputs/music/track.mp3", "start": 12.0},
  "subtitles": {"enabled": true, "file": "subs.srt"},
  "texts": [{"text": "ريحة تدوم نهار كامل", "start": 0.2, "end": 2.2, "pos": "top"}],
  "end_card": true,
  "cover_at": 1.2,
  "shots": [
    {"src": "inputs/video/01.mov", "in": 1.2, "dur": 1.6, "focus_x": 0.42},
    {"src": "inputs/photo/flacon.jpg", "dur": 2.6, "move": "push_in"},
    {"src": "inputs/video/02.mov", "in": 0.5, "dur": 2.1, "speed": 0.5, "stabilize": true},
    {"src": "inputs/video/03.mov", "in": 4.0, "dur": 2.4,
     "transition": "crossfade", "transition_dur": 0.4, "grade": {"brightness": 0.03}},
    {"type": "card", "dur": 1.8, "transition": "fadeblack", "transition_dur": 0.5}
  ]
}
```

Shot fields:

| field | meaning |
|---|---|
| `src`, `in`, `dur` | source file, in-point in the source (s), length on screen (s) |
| `transition`, `transition_dur` | how this shot **enters** from the previous one: `cut` (default) or one of the brand's `allowed_transitions` |
| `focus_x`, `focus_y` | 0..1, where to keep the subject when cropping to 9:16 |
| `zoom` | 1.0-1.3 punch-in on a video (a second angle from the same take) |
| `speed` | 0.5 for slow motion (best from 60 fps footage), up to 2 |
| `stabilize` | two-pass vidstab for handheld shots |
| `keep_audio`, `audio_gain_db` | real sound from the clip; default is the brand's ambient level |
| `move`, `amount` | photos: `push_in`, `pull_out`, `drift_left/right/up/down`, `static`, and the zoom amount |
| `grade` | per-shot correction: `brightness`, `contrast`, `saturation`, `gamma`, `warmth`, `denoise` |
| `type: card` | the brand end card (background colour + logo) |

`texts` are the on-screen titles (the hook line from `/ig-reel`), styled by
the brand's `titles`. `pos` is `top`, `center` or `bottom`.

### 5. Check, preview, final

1. `check` until it reports no errors. Read every warning and either fix it
   or say why it stays.
2. Tell the user the cut in a few lines (shots, length, transitions, music
   level) and ask before rendering.
3. `render --preview`, send the file with SendUserFile, and collect notes.
4. Apply the notes in `edit.json` or `subs.srt`, then `render --final`. Each
   render gets a new version number (`-v2`, `-v3`) and a cover JPEG. The
   exact commands are saved in `out/work/commands.sh`.

## What the engine does on every shot

- 9:16 crop with lanczos scaling at `focus_x/focus_y`, 30 fps.
- iPhone HDR (HLG/PQ) tone-mapped to SDR so it doesn't wash out on Instagram.
- Light denoise, the brand grade (contrast, saturation, gamma, warmth,
  optional `.cube` LUT), gentle sharpening, optional vignette, fine temporal
  grain so photos and video share a texture.
- Photos: upscaled 2x before the move, smoothstep easing.
- Voice: high-pass, denoise, de-ess, compression, presence EQ, set to the
  brand loudness. Music: set to its brand loudness, sidechain-ducked under the
  voice, faded in and out. Master: two-pass loudnorm to −14 LUFS.
- Export: H.264 High, CRF 17, BT.709, AAC 256k 48 kHz, faststart.

## Brand profiles

`brands/<slug>/brand.json` holds the look, pacing, audio, subtitle and title
styles, and the end card. `brands/<slug>/fonts/` takes the brand's `.ttf`
files, `brands/<slug>/logo.png` the logo (transparent PNG), and an optional
`.cube` LUT goes next to it (set `look.lut`). Each profile has a
`to_confirm` line: the Vitaya RELAX profile in particular is a starting
hypothesis until the user confirms what the brand is and how it looks.

## Before you finish

- Run `check` once more on the final `edit.json`.
- Commit `edit.json`, `script.txt` and `subs.srt` (the recipe). Media and
  renders stay out of git (`reels/**/inputs`, `reels/**/out` are ignored), so
  remind the user to download the final file: the cloud container is erased.
